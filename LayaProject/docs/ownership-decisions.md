# World、UI 与事件归属判定

用于新增功能或改变归属时的开发决策。先从用户要求、当前游戏约定、调用方和退出行为确定事实；现有归属明确的局部修复不重新设计。功能名称、窗口大小、文件数量不能代替生命周期依据。

## 决策与澄清

分别确定业务状态、注册定义、运行实例、事件源和订阅的持有者。选择能覆盖实际使用期的最小现有 owner，并用一句话说明归属、进入与退出行为；这是实施说明，不是固定审批表。

只有无法查明且会改变结果的产品行为才问，例如“切到战斗后，这个窗口是否继续显示？”；不要让开发者回答“这是公共 UI 还是场景 UI”这种技术分类题。已明确的答案不重复询问；等待期间继续无依赖工作。

已要求实现某玩法，且进入、退出和状态保留行为明确时，可按现有 BaseWorld 契约建立游戏 World，无需重复批准。改变框架共享契约、全局数据寿命或未授权的产品行为仍按根 AGENTS 处理。

## 是否建立独立 World

需要独立进入、整体退出的一段业务运行期，且现有 Scene/UI 的寿命不足以管理它时，建立独立 World：它拥有本次运行状态、订阅、任务或资源，退出需要整体失效，再次进入重新初始化。无需为了凑齐种类添加空模块。

- 一场战斗包含本局状态、暂停或倍速、HUD 和场景，退出结束整局，通常适合 BattleWorld。
- 同一局内换地图且战斗状态继续存在，优先在同一 World 中切换 Scene。
- 大厅的背包、商城、设置只是界面功能时，留在现有 World；复杂或全屏本身不构成新 World。
- 独立玩法具有自己的进退与运行状态时可建立新 World；共存、暂停保留或退出重建由业务要求决定，不默认只有一个活动 World。

World 是普通 TS 对象。工厂在游戏组合根集中登记；子类只覆写 BaseWorld 的准备、事件、UI、场景、进入和退出钩子，公共调度与自动卸载由父类及 WorldScope 处理。按需使用原生 timer 和局部 delta 倍率，不建立全局 Update。

## UI 定义、实例与数据

| 需求 | 定义与实例归属 |
| --- | --- |
| 多个 World 确实使用同一物品详情或确认框 | 根登记共用定义；打开的实例仍归调用它的 Scene 或父展示 |
| 本场战斗专用 HUD、结算界面 | 本 World 注册定义，实例归对应 Scene |
| 背包关闭时一同结束的确认框 | 使用 session.show，实例归背包本次展示 |
| 关闭当前页面后仍在本场景显示的独立面板 | 使用 session.ui.show，实例归 Scene |
| 必须跨 World 切换继续显示的应用窗口 | 根持有应用窗口，通过 lx.ui 使用原生 GRoot/GWindow |

公共定义不代表全局常驻实例。全屏/弹窗是布局，层级是显示顺序，均不决定生命周期；可复用美术组件也不自动成为公共窗口。只有一个消费者时不因“以后可能复用”上移定义。

账号数据、红点状态与规则由根初始化，首次同步完成后才进入初始 World；具体游戏模型仍放在 game。World/UI 退出只释放自己的表现、订阅和局部状态，不清空账号数据。窗口关闭不丢弃应写入全局模型的业务结果，只有表现回写检查失效令牌。

## 事件源与订阅

| 内容 | 事件源与处理位置 |
| --- | --- |
| 框架 READY/STOPPING、跨业务有效的账号状态通知 | 根持有公共源或对应全局模型的原生事件源 |
| 本局下一波、局部暂停、某 World 发起的导航请求 | 本 World 的 events；本类 registerEvents 登记处理 |
| 按钮点击、界面内部选择 | 原生 UI 事件或直接调用，未有解耦需求时不额外广播 |

根据事件表达的事实及其有效期判断，不能因为经过 WebSocket 或未来可能有多个监听者就放进全局总线。跨 World 协调通过明确的公共事实或注入的导航函数，不能互读内部对象。

事件源归根不代表所有订阅归根：World 用 world.listen 登记对任意源的订阅，退出精确 off；UI 对长期源的订阅归当前展示，关闭/隐藏时解除。不能让 UI 监听一直留到 World 退出，也不能在小 World 退出时清空 lx.events。模型变化可在模型自身的原生事件源通知，不建立第二套事件系统。

## 代码位置与验收

游戏内全局、公用功能仍属于当前游戏。只有已证明稳定复用的引擎无关能力或通用适配才考虑框架；下游实施位置按根 AGENTS 已确认的选择处理。归属改变不意味着新增 Service、Context 或 Host。

验证依据实际影响选择：只读归属诊断不运行构建；归属说明只查差异与链接；修改 Skill 决策按工作流规则验证；TS 变化检查类型与相关行为，依赖变化加架构检查。World/Scene/UI 退出语义改变才补对应原生清理探针；仅监听、取消或命名调整不附带分辨率矩阵。相关输入未变的证据复用，不重复完整发布验收。

具体 API 与清理顺序见 [World 生命周期](world-lifecycle-design.md)、[场景流程](scene-flow.md) 和 [UI 数据绑定](ui-data-binding.md)；验证选择见 [工作流规则](../.agents/skills/codex-workflow/references/workflow-rules.md#verification)。
