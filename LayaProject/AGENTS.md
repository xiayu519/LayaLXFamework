# LXFamework

请使用中文写提案和回答；代码标识、命令、路径、API 名称及日志保持原样。项目由 2–3 人协作。主线程与任务门禁固定使用 `gpt-5.6-sol/high`，Plan mode 使用 `xhigh`，输出保持精简；已通过门禁的低风险小任务允许使用低成本执行代理，主线程负责复查与验收。

业务请求应说明目标、目标平台、验收结果和硬约束，无需指定 Skill 或实现步骤。Codex 根据语义选择范围最窄的项目 Skill；只有任务跨越独立风险边界时才组合多个 Skill，并且只读取当前任务需要的 reference。

共享框架放在 `src/framework/`，游戏业务放在 `src/game/`；framework 不得依赖 game，业务运行时只经 `LX` 入口。写入前复查目标文件并保留他人改动；同一语义区域出现并行冲突时停止并报告，不猜测覆盖。

持有监听、Timer、异步回写或资源租约的对象必须由 owner 在 Hide/Destroy/Stop 时逆序释放。

业务中出现开发者纠正，或发现可能要改变共享框架/工作流时，立即按最新语义停止该边界写入。不能证明跨业务复用与稳定语义则保留在业务层；能证明才提交 Change Contract，获批后继续，并在验证后沉淀可复用纠正。

评审、诊断和方案分析默认只读；实现、修复类请求应完成范围内改动和相应验证。会改变结果的不确定性先对齐；已批准的 Change Contract 在语义边界未变化时不重复确认。

除非开发者明确要求 GUI，验证均在当前项目原地、纯 Headless 执行：不得复制项目，不启动 LayaAirIDE 或可见浏览器；独立检查可并行，无相关改动不重复执行。运行时验收使用 LayaAir 3.4.1 CLI 构建，并由 Headless Chromium 检查真实 2D 发布包。

完成时只报告实际改动、验证结果、未验证项和剩余风险，不追加范围外工作。
