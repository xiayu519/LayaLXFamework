# Shared promotion criteria

## Keep in game

满足任一项时保留在 `src/game/`：

- 只有一个具体玩法、页面、活动或项目消费者。
- API 使用当前业务词汇，生命周期随玩法快速变化。
- Laya 已提供足够语义，只需要当前业务的参数组合。
- 公共化依赖对未来复用的猜测，没有现有证据。

## Candidate for framework

同时满足以下条件才可提出上移：

1. 至少两个独立真实消费者；或者属于必须统一的持久化、支付、安全、平台、资源或生命周期不变量。
2. Laya 原生能力不能直接满足该业务语义，且新增层不是纯转发。
3. API 不携带单一玩法词汇，输入、输出、所有权、失败与释放边界稳定。
4. 上移能减少重复维护，不迫使无关模块依赖额外状态或服务。
5. 可以给出自动验证、兼容/迁移方式和明确负责人影响范围。

通过只表示“可以提交公共变更契约”，不表示已经获准写入 framework。公共框架与工作流都属于多人共享边界，必须在批准后实施。
